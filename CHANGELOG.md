### Added
- **Roadmap-2 Phase 5b — Pre-commit AI review hook (warn-only by default).** Right-click a project → **🔍 Pre-commit AI Review hook…** to install or remove a git pre-commit hook that reads `git diff --cached` and runs an AI code review before letting the commit through. Architecture in three pieces:
  - **`src/helpers/precommit_hook.py`** — install / remove / detect helpers + the review runner. Uses a sentinel marker (`# TOKENSAVE-PRECOMMIT-MARKER v1`) inside the hook script so install/remove are symmetric and refuse to touch a hook the user installed themselves. Severity parser (`parse_severity_summary`) counts `- ` bullets per `## ⚠ High` / `## ⚡ Medium` / `## 💡 Low` / `## ℹ Observations` section using the Stage 1 reviewer system prompt format. Threshold logic (`severity_blocks_commit`) maps `precommit_severity_threshold` ∈ `{"none", "high", "medium"}` to a block decision.
  - **`src/precommit_review.py`** — the standalone Python entry point the hook script invokes. Bootstraps `sys.path` to the manager's `src/`, reads the cached diff, loads `ManagerConfig`, dispatches to a backend, parses the result, prints findings to stderr, exits 0 or 1. **Fail-open invariant**: every error path (no diff / config missing / backend failure / unparseable output / unhandled exception) exits 0 with a stderr notice — never blocks a commit because the AI is sick. A master try/except wraps `main()` so even pure crashes can't break user commits.
  - **`src/controllers/git_ops_ctrl.py`** — new `cmd_precommit_hook(path)` shows a confirm dialog with current backend + threshold and flips install state. Split into `_do_precommit_install` and `_do_precommit_remove` helpers + a `_precommit_status_blurbs` reader; orchestrator stays under the method caps. Wrapper in `controllers/projects_tab.py` + a single menu item under the existing Git cluster.
  - **Three-value backend choice** (`precommit_review_backend` in `manager-config.json`): `"auto"` (default — prefer Claude Code CLI subscription if `claude_cli_exe` is set, fall back to the configured `_call_llm` provider), `"claude_cli"` (force Claude Code CLI via `claude --print --append-system-prompt`), `"llm"` (force the manager's configured per-token provider). Same cost-control principle that drove the Roadmap-1 Claude CLI hand-off integration — users with a CC subscription can route the review through it without spending API credits.
  - **Recursion guard** via `TOKENSAVE_PRECOMMIT_RUNNING=1` env sentinel. The hook shell script sets it before invoking the reviewer; the reviewer's entry path exits 0 immediately if it's already set. Cheap insurance against a future failure mode where the reviewer itself triggers a git commit somewhere.
  - **Hook script is plain POSIX sh** with hard-coded absolute paths to the user's `python_exe` and the reviewer script. Runs under Git for Windows' bundled MSYS shell so cross-shell quoting isn't a concern. If either path is missing at hook-fire time, the script exits 0 with a stderr notice — moving the manager doesn't break commits.
  - **Cap snapshot**: `helpers/precommit_hook.py` (0 violations), `precommit_review.py` (0 violations), `GitOpsController` 9 → 13 methods (still well under 40). `ProjectsTabController` 44 → 45 methods, one over cap — acknowledged in the existing Roadmap-3 backlog entry for that controller; a thin wrapper for a real feature is acceptable cost.
  - **End-to-end verified** against a throwaway git repo: install / re-install (idempotent) / detect-installed / refuse-to-overwrite-user-hook / refuse-to-remove-user-hook / clean remove / detect-not-installed all pass.

- **Roadmap-2 Phase 5a — "Open PR on GitHub" button in the PR draft dialog.** Right next to "Copy to clipboard" in the dialog produced by the existing Git-tab `Draft PR…` button. Writes the AI-drafted body to a temp `.md` file in `%TEMP%`, then spawns `gh pr create --web --body-file <tmp>` with `cwd=<project_path>`. `--web` opens the GitHub New-PR page in the default browser with the body pre-filled; the user picks title, base branch, and draft state there. Using `--body-file` (rather than `--body "..."`) avoids Windows command-line length limits AND quote/newline escaping problems entirely. The temp file is intentionally left on disk — `gh` reads it lazily after the browser opens, so deleting it eagerly would race; `%TEMP%` cleanup happens at the OS level. The button is greyed out and tooltipped with an install hint when `shutil.which("gh")` returns nothing. Failures (no remote, gh not authed, no commits to PR, etc.) surface as a `messagebox.showerror` parented to the dialog so users aren't left wondering why nothing happened. `_show_pr_draft_dialog` gained a `path: str` parameter (was previously just `text` — the caller now threads `path` through from `_draft_pr_via_api` to the button's lambda).

- **Roadmap-2 Phase 1 — Stage 3 unlock: `write_file` tool + `ProposalDialog` bridge.** The Ask-tab agent can now propose file edits, gated behind the existing `ProposalDialog`. End-to-end flow:
  - **New `write_file` tool in `agent_tools.py`** (`is_write=True`). Tool description forbids blind rewrites on files over 400 lines (model is instructed to prefer minimal edits). `ToolSpec` gained two new fields: `proposal_builder(args) -> WriteProposal | error_str` (validates + builds the proposal shown to the user) and `post_accept(proposal, final_content) -> result_str` (does the actual atomic write after user accepts). Read tools are unchanged. `build_tools(..., with_write=True)` opt-in keeps the registry backwards compatible.
  - **Race-safe writes.** Each proposal captures `original_hash = sha256(original_content)` at build time. `post_accept` re-reads the file at write-time and aborts if the hash differs ("user edited the file while the proposal was open" — model gets a `[write rejected: file changed on disk ...]` string and is told to re-read). `original_mtime` is captured too but used for diagnostics only — hash is authoritative because timestamps drift across git checkout / OneDrive / FS precision. New-file path also detects race (file created between build and accept).
  - **Symlink-safe path containment.** `_under_project()` already uses `os.path.realpath` on both sides; `write_file` adds an explicit `os.path.islink(full)` check to refuse overwriting a symlink target outright (avoid traversal surprises).
  - **Side-effect surfacing.** Missing parent directories are computed at proposal-build time and shown in the dialog ("Will also create: `nested/missing/dir/`"). On accept, `os.makedirs(parent, exist_ok=True)` runs before the atomic `.tmp + os.replace` write.
  - **New `ProposalBridge` in `dialogs/proposal.py`** coordinates the agent worker thread ↔ Tk main thread. `invoke()` is called from the worker; it schedules `ProposalDialog` on the main thread via `root.after(0, ...)` and blocks on a `threading.Event` (5-min timeout). Disk I/O happens on the worker thread, not Tk main — keeps GUI hitch-free under AV / OneDrive / Defender stalls. `_resolve()` is idempotent under a `threading.Lock` so late clicks after timeout, double-callbacks, and external cancellation can't race.
  - **`ProposalDialog` hardened.** New `on_reject` kwarg lets the bridge signal cancellation back to the worker. `WM_DELETE_WINDOW` protocol wired so window-close button and Alt-F4 both count as reject (agent never deadlocks). New `show_expired()` switches the dialog into post-timeout read-only state: Accept/Reject disabled, expired banner shown, Close button surfaced — dialog stays open so the user can still read the diff. **No auto-close** (would surprise users mid-read). `dirs_to_create` displayed prominently in the header when non-empty.
  - **`WriteProposal` dataclass extended** with `original_hash`, `original_mtime`, `dirs_to_create` fields, all defaulted so the standalone test harness keeps working unchanged.
  - **`LocalAgent.__init__` gains `on_write_proposal: Callable | None = None`** — backwards compatible default of None preserves the original read-only invariant for any caller that doesn't opt into write support. `_dispatch_tool` routes `is_write=True` tools through `proposal_builder → on_write_proposal → post_accept`. Defence-in-depth: if a write tool slips into the registry without a configured bridge, it's refused with `[tool error]` rather than silently executing.
  - **App-shutdown invariant.** `AskTabController` tracks active bridges in a `set` (mutated under a `Lock`). `App._quit_app` calls `cancel_all_proposals()` before `destroy()` so worker threads waiting on open dialogs are released cleanly — no hung daemons on tray-Quit. Hide-to-tray does NOT cancel; the user can recover an open proposal by clicking Show.
  - **Inline test harness in `proposal.py.__main__`** drives four race-safety paths: late-resolve no-op, cancel releases waiting worker, concurrent _resolve race-safe, invoke() no-deadlock without mainloop. Run via `python src/dialogs/proposal.py --no-ui` for automated, or without `--no-ui` for interactive Accept / Reject / Close click-through. The four automated tests all pass.
  - **Pre-Phase-1 cleanup:** `src/tokensave-wrapper.py` got a top-of-file `# anti-monolith: exempt — MCP wrapper, must stay single-threaded; see docs/MCP_INTEGRATION_GOTCHAS.md` comment so Doctor stops flagging `find_project()` complexity on every run. - **`tokensave-wrapper.py` Popen now passes `stdin=sys.stdin, stdout=sys.stdout, stderr=sys.stderr` explicitly — fixes MCP connection timeout that was actually a stdio-inheritance bug, NOT a threading bug as previously believed.** Symptom: Claude Desktop banner `Could not attach to MCP server tokensave`; per-project `mcp-logs-tokensave/*.jsonl` reporting `Connection timeout triggered after 30040ms (limit: 30000ms)`. ## [1.0.2] — 2026-05-21

Patch release. Fixes the **three-headed commit bug** that made the v1.0 / v1.0.1 Untrack-Ignored-Files workflow unusable in practice. Each fix peels off one layer of the onion:

### Fixed
- **`_do_git_commit` no longer runs `git reset` before staging.** The original reset was there to "clear the index so nothing already-staged sneaks into the commit" — but the cost was destroying intentional stagings like `git rm --cached` (the untracking operation the new 🧹 flow performs). The new behaviour: skip the reset entirely, use `git commit -m <msg> -- <paths>` (path-specific commit) so only the listed paths land in the new commit regardless of what else might be in the index. Standard git pattern; makes the index-reset unnecessary.
- **`_do_git_commit` no longer blindly `git add`s every selected file.** Files that are already fully staged (xy column 1 == `' '`, e.g. a `git rm --cached` queued by 🧹 Untrack Ignored Files appears as `D ` — staged-delete with no working-tree change) don't need re-adding. Worse: calling `git add` on a staged DELETION un-does the deletion and tries to re-add the file, which fails if the file matches a `.gitignore` rule — leading to the exact failure mode the 🧹 flow was supposed to prevent. Fix: GitCommitDialog now passes `(fname, xy)` tuples to the worker, and the worker only calls `git add` on files whose xy column 1 is not space.
- **Better error surfacing when `git add` does hit an ignored file** (e.g. user explicitly ticked an already-tracked-but-ignored file in the dialog). Previously the manager just logged `git add failed: <raw git output>`. Now it detects `ignored by one of your .gitignore files` in the output and shows a dedicated dialog with the affected paths listed and a one-line action to fix it.

### Added
- **Pre-flight tracked-but-ignored check in `_open_commit_dialog`.** Before opening the commit dialog, the manager runs `_find_tracked_but_ignored(path)`. If any matches exist, it shows a 3-way choice: **Yes** → open Untrack Ignored Files first (recommended); **No** → open the commit dialog anyway; **Cancel** → close, do nothing. This proactively breaks the cycle instead of waiting for the commit attempt to fail.

### Internal contract changes
- `GitCommitDialog` callback signature is now `callback(path, message, selected: list[tuple[str, str]])` — each tuple is `(fname, xy)`. The old `list[str]` form is still accepted for backward-compat (unknown XY is treated as needs-add, which is harmless because git add is idempotent).
