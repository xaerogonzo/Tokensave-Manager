**Release Wizard and README fragments.** If the project has a `readme.d/` folder, 📦 Release… folds its fragments into `README.md` for you, in the same `chore: release prep for <tag>` commit that stamps the CHANGELOG and removes the changelog fragments: one commit holds `README.md` and every removed `readme.d/` file. The confirmation says how many README fragments it will fold. It happens whether or not the CHANGELOG sync box is ticked, and before the build, so a built Manager's Help shows the folded text. An invalid README fragment blocks Publish before anything is changed, the same as a changelog fragment does. If a step fails, every fragment stays on disk; the message names the exact `git restore --staged --worktree README.md readme.d` that undoes it, and re-running reads the fragments as already folded and changes nothing twice. The pre-flight accepts a changed `README.md` only while fragments are pending.
