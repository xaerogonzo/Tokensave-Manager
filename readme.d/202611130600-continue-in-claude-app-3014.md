**Continue in Claude app…** (on a Cursor row) is for people who work in the Claude desktop app rather than its terminal. It asks first, writes the same brief and conversation file, puts one short message on your clipboard that names them, then asks Windows to open `claude://code/new?folder=…&q=…` so the app starts a new session on the folder with that message in the box. Three things it cannot promise, and says so: a folder opened from a link is always untrusted, so Claude asks you to trust it each time; Windows accepting the link is not proof the app opened or filled the box (one report says an already-running app may ignore it), which is why the message is on the clipboard first and shown in the dialog; and it needs the `claude://` handler the desktop app registers. A Cursor chat whose folder was matched exactly opens there; one that looks like a `_scratch` checkout of a known project opens the project folder after telling you its own checkout was not identified; an ambiguous or unknown one has no folder, and the dialog says why instead of guessing. Claude Desktop starts a session for a repository that has a commit in a NEW WORKTREE of the folder, where the git-ignored `.tokensave/` folder does not exist, so the message names the brief and the conversation file by absolute path and says where the main checkout is (that is also where uncommitted changes are). The terminal entry keeps its behaviour under the name **Continue in Claude (terminal)…**.
