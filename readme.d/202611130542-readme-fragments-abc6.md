**README fragments.** A pull request does not edit `README.md`; it adds a file under `readme.d/` whose first line names the section (`<!-- readme: tasks-tab -->`, a key from `python scripts/readme_fragments.py targets`) and whose body is the Markdown to append there, so two PRs documenting the same section cannot conflict. `python scripts/readme_fragments.py check` validates them (it runs in the test suite), `preview` shows the README `build` would write, and `build` folds them in and deletes them when a release is prepared. Until then the README, and the in-app Help from a checkout, does not show a pending fragment. `readme.d/README.md` has the rules.
