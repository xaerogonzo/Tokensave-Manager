### Changed
- (release) **The Release Wizard hands over to a project's drafting release workflow instead of racing it.** Both used to create the release: the Wizard built, zipped and ran `gh release create` after pushing the tag, the tag then triggered `.github/workflows/release.yml`, and that workflow's draft job (rightly) refuses to touch a release that already exists, so one of the two always failed and a version could end up with files from two different machines. Now, when the project has a workflow that reacts to `tags:` and creates its release with `--draft` (`_release_workflow_drafts`, a deliberately small text check; a workflow that would publish by itself is not handed anything), the Wizard runs: check the tag, write the CHANGELOG section, commit, tag, push, and stops. It builds nothing, zips nothing and creates no release; the Build and Artefact steps say so, the confirmation describes a draft, and the finish message says the workflow is drafting. Two safeguards come with that, both about failures that would otherwise surface only AFTER the tag is on the remote: `_pub_check_tag` runs the project's own `scripts/release_info.py check-tag` first (the workflow refuses a tag that is not `v` + the source's version), and a check that could not run (no `python`) fails instead of passing; and the CHANGELOG step is required in that mode, because the workflow takes its notes from that section. A project without such a workflow keeps the whole pipeline unchanged. `tests/test_release_wizard.py` gains 21 tests (the detection, both pipelines' step lists, halting at each failure, the draft wording, the tag check in all four outcomes, the confirmations and the refusal); six mutations (the flag ignored, a non-draft workflow accepted, the changelog requirement dropped, a mismatched tag passing, a check that could not run passing, a published-release message) each fail them. Not exercised: the dialog itself with a real window, and the first real tag. (`src/dialogs/release_wizard.py`, `.github/workflows/release.yml`, `docs/RELEASE_CONTENTS.md`)
