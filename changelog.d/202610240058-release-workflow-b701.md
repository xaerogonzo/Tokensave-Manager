### Added
- (release) **A draft-only release workflow (`.github/workflows/release.yml`).** A `v<version>` tag push builds the release on a clean Windows runner with `build.ps1 -Release` (all frozen-smoke layers on `dist\` and on the extracted zip), checks the checksums, attests where the zip came from, and creates a DRAFT GitHub Release whose notes are that version's CHANGELOG section; a person reads it and presses Publish. The tag and the changelog section are checked before the long build. A pull request that changes how a release is made runs the same build as a dry run (no attestation, no release). Permissions are none by default, `contents: write` exists on the draft job alone and only for a tag push, every third-party action is pinned to a full commit SHA, and no expression is interpolated into a script. The smoke's configured layers need a real tokensave, so the runner installs tokensave 7.16.0 pinned by version and by the sha256 of its Windows asset (from the maintainers' own `SHA256SUMS`, which catches a replaced or damaged download, not a compromised release). The draft job refuses to touch a release that already exists, because the Release Wizard creates one itself and two sources for one version's files is what a draft-only flow exists to prevent; use one path per release. Not an installer and not a code signature: SmartScreen still says "unknown publisher". `tests/test_release_workflow.py` holds the draft flag, the single writer job, the SHA pins, the no-interpolation rule, the pinned tokensave and tools, and that every path in the pull-request filter exists; four mutations (draft flag removed, an unpinned action, an expression spliced into a script, write access on the build job) each fail it. The workflow itself can only be exercised on GitHub. (`.github/workflows/release.yml`, `tests/test_release_workflow.py`, `docs/RELEASE_CONTENTS.md`)
