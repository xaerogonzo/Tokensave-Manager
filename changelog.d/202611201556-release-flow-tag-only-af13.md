### Added
- (release) **The Release Wizard recognises how a project is built and who makes its release, and for a project that opts in it only checks, plans and runs the TAG.** `helpers/release_profile.py` reads a project's build system (Nuitka, PyInstaller) and installer (Inno Setup) from marker files and says which evidence it used; whether the workflow drafts the release decides the flow, not the compiler. A project with a drafting `release.yml` AND a `release-flow.json` gets a pre-flight (version, tip up to date with origin, the project's own tag / changelog / fragment scripts, existing tag and draft, CI on the tip) where an unreadable source is `unknown` and never a tick; the exact commands for the current origin tip, including the re-tag case (delete a DRAFT release and the remote tag, move the local tag, push); and, after the build, a check of the draft's assets, `SHA256SUMS.txt`, tag commit and workflow run, then a manual installer checklist with ticks kept per tag. Only four command shapes can ever be produced or run (never a branch push, a force, or a publish); the tip is re-read before every Run, and anything that leaves the machine needs the tag typed. A published release is refused. Projects without `release-flow.json` keep the previous Wizard unchanged.
