### Added
- (tasks) **"Continue in Claude app…" on a Cursor row, for people who work in the Claude desktop app, not its terminal.** The terminal handoff started Claude Code in a console window; the app's agent cannot be launched from outside, so the Manager does what the app's documented link allows. After the same confirmation it writes the deep brief and conversation file, puts one short message on the clipboard, then asks Windows to open `claude://code/new?folder=<path>&q=<message>` (new `helpers/claude_app.py`: every value URL-encoded on its own, an absolute folder required, a message over 2000 characters refused because the link carries only the instruction, never a brief; the `claude://` handler is checked in the registry first). The order is deliberate: clipboard BEFORE the link, so a link Windows refuses leaves one paste to finish, and the dialog says "Windows was asked to open a new Claude session", never that Claude opened, because `os.startfile` returning means the OS accepted the link and nothing more (a folder opened from a link is also always untrusted, so Claude asks to trust it, and one report says an already-running app may ignore the link). If the brief cannot be written no link is opened. The old entry is renamed "Continue in Claude (terminal)…". Chats whose folder was resolved rather than recorded now follow their resolution for BOTH Claude entries: `project_only` opens the project folder after saying the chat's own checkout was not identified, `ambiguous` and `unmatched` have no folder and say why instead of guessing. Verified live on this machine (Claude Desktop already running): the link reaches the running app, which shows the new-session screen and asks to trust the folder EVERY time (as documented); on the first attempt the app went back to the previous session after the trust click and no session started, on the second it started one whose first message was exactly the handoff message. A repository with a commit gets the session in a NEW WORKTREE, where the brief's relative path `.tokensave/handoffs/x.md` failed ("File does not exist"; the session recovered only by looking in the parent), so the message now uses absolute, backtick-quoted paths and says where the main checkout is and that uncommitted changes live there; with that the first read succeeded, and the original Cursor transcript outside the workspace was readable with no permission prompt (the test session was in Auto mode; default mode is untested). (`src/helpers/claude_app.py`, `src/helpers/agent_handoff.py`, `src/controllers/tasks_tab.py`, `tests/test_claude_app.py`)
