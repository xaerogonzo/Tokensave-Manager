### Changed
- (handoff) **The ledger now lives in git's common directory, so every worktree shares it.** It had been `.tokensave/handoff.jsonl` inside each checkout, and a linked worktree's folder is not shared with its siblings: a handoff written in one worktree was invisible from another worktree of the same repository, which is exactly how these sessions are run. In a repository the ledger is `<git common dir>/tokensave/handoff.jsonl`, found with `git rev-parse --path-format=absolute --git-common-dir` (older git is asked again without the flag), which every worktree of a clone shares and git never tracks, so the `.gitignore` question disappears for it. Only a folder with a `.git` of its own counts as a repository: `git` walks upward, and a plain folder nested in someone else's repo would otherwise have its ledger filed inside its PARENT's `.git`. Such a folder, and any non-repository, keeps `.tokensave/handoff.jsonl` and keeps the warning when git would not ignore it. The git answer is remembered, a miss or a missing git is not, and `status` reports `location` as `git` or `project`. Checked on this repository: published from this worktree, listed from the main checkout, branch recorded, nothing for `git status` to show. Mutation-checked by asking git for the per-worktree directory instead (sibling worktrees stopped seeing each other) and by dropping the own-`.git` rule (a nested folder landed in its parent's `.git`). (`src/helpers/handoff_ledger.py`, `src/cli.py`, `tests/test_handoff_ledger.py`, `tests/test_cli_handoff.py`)
