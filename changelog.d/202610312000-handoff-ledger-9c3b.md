### Added
- (handoff) **A shared handoff ledger, and a command agents publish to.** `.tokensave/handoff.jsonl` is append-only, one entry per line, written by `manager-cli handoff --action publish --agent <id> --goal ... --decision ... --next-step ... --question ... --file ...`. It is **opt-in**: nothing is written unless `enable_agent_handoff` is a literal `true` (a string, `1` or `"yes"` is not consent), and a refusal is the prerequisite exit code rather than a quiet success. The agent supplies only its own words; the branch, base commit and the files git reports as changed are measured by the Manager, and an agent's claim about what it changed is stored separately from what git saw. Entries are bounded (every string and list is capped and what was cut is named in `truncated`), secrets are masked best-effort, newlines are flattened, an empty handoff is refused, and the id is a hash of the content so a retry after a timeout writes nothing twice. Two agents finishing together are safe: appends take a lock file that is broken only when stale, a partial earlier line cannot glue to the next entry, and lines that do not parse are counted and reported, never dropped. Over 200 entries or 512 KB the file is cut to the newest 150. `status` and `list` work whether or not it is on and `clear` needs `--yes`; the CLI warns when git would not ignore the ledger. Checked with real processes (five writers, forty entries, none corrupted) and by breaking idempotency, the newline glue, bad-line counting and the consent check one at a time.
