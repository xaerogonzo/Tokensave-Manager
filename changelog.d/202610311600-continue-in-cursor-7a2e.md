### Added
- (tasks) **Continue in Cursor… (right-click a Claude session).** Cursor's own Claude importer did not run on this machine and is not something the Manager can switch on, so the Manager hands the work over itself. It finds the folder the session ran in, builds a brief from the transcript and opens Cursor's agent there pointed at it. The brief keeps three kinds of statement in separate sections and says so at the top: what the person asked (their words, secrets masked best-effort, harness text such as `<system-reminder>` and `<task-notification>` removed), what Claude last said (a claim, not a fact) and what git reports now (branch, uncommitted files, recent commits). It is written to `.tokensave/handoffs/` (git-ignored), not put on the command line, because cmd.exe caps that near 8 KB and strips newlines. Nothing is written until the person confirms, and the dialog says it is a handoff, not an import, and that Cursor will send the file's contents to its service. Live-checked: Cursor read the brief and reported its branch, change count and opening words correctly. Claude's memory and the full transcript do not come across, and Cursor -> Claude is not built. (`src/helpers/agent_handoff.py`, `src/controllers/tasks_tab.py`, `tests/test_agent_handoff.py`, `tests/test_tasks_tab_sessions.py`)

### Changed
- (sessions) **`scan_sessions` rows now carry the transcript `path`, and `session_context.scan_transcript` reads one transcript with a per-call fragment cap.** A session id is not unique on disk, so a caller that needs the file must not rebuild its name from the id; the window scan keeps its 600-character cap, which cut a real original request mid-sentence. (`src/helpers/claude_tasks.py`, `src/helpers/session_context.py`)
