### Fixed
- (release) **In workflow mode the Release Wizard no longer shows a title that is not the release's title, or an artefact that is not the artefact.** The Wizard's title field defaults to the version plus the first 60 characters of a commit subject, a hint that read as a truncated sentence ("…the Wizard hands over to a project's drafting rele"). With a drafting release workflow it was also not the release's title at all: the workflow titles the release itself, and the field only becomes the git tag's note. The default there is now plain (`Release v2.7.0`) and the Title step says what the text is for; a project without the workflow keeps the old hint. The Artefact step had the same trap in a different form: it was set once, to say the workflow builds the files, and the first change to the version refreshed it into a listing of the local `dist/` (stale files, and a `manager-config.json`) that is not what gets released. The refresh itself now knows the mode. Four tests, two on the real dialog (the label and title after a version change, and that a project without the workflow is unchanged); three mutations (the artefact refresh listing `dist/` again, the title keeping the cut subject, the title note dropped) each fail them. (`src/dialogs/release_wizard.py`, `tests/test_release_wizard.py`)
