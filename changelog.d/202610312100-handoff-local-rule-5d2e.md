### Added
- (handoff) **Agents are told about the handoff command by a git-ignored `CLAUDE.local.md`.** `manager-cli handoff --action rule` writes one marked block naming the exact command (the same interpreter, script and config the Manager's own VS Code tasks use), and `--action unrule` takes it out, leaving anything else in the file. It holds this machine's paths, so it must never reach a commit: the name is added to `.git/info/exclude` (resolved with `git rev-parse --git-path`, so a linked worktree finds the shared one) **before** the file is written, a file that is already tracked is refused and left untouched, and `status` reports the rule as absent, current, stale (the Manager moved) or tracked. One file is enough for both agents. Measured with canary lines in two excluded files: Claude Code loaded `CLAUDE.local.md`, and Cursor loaded both it and its own `.cursor/rules/*.mdc`, so a second file for Cursor would have put the instruction in its context twice. Checked live: a real Claude and a real Cursor agent each read the file and produced a working command under their own name, and running both wrote two entries to the ledger. Refused while handoff is off. (`src/helpers/handoff_rules.py`, `src/cli.py`, `src/helpers/agent_rules.py`, `tests/test_handoff_rules.py`, `tests/test_cli_handoff.py`)
