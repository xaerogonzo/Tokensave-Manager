### Fixed
- (tasks) **Cursor desktop chats are now listed in History.** The Manager read only the terminal agent's `~/.cursor/chats/*/meta.json`; the desktop app keeps no such file, so its chats existed only as transcripts and were invisible: 74 transcripts on the measured machine, 49 listed, and every recent desktop chat missing, which also meant "Continue in Claude" could not be offered for them. They are now read from `~/.cursor/projects/*/agent-transcripts` (new `helpers/cursor_transcript.py`, a bounded head read, no UI or session imports) and merged with the terminal chats by chat id: the metadata title and a real metadata folder win, the transcript fills what is missing, the metadata's own activity time is kept (a transcript's file time moves with a copy or a touch), and the row carries the transcript path. A transcript records no folder and Cursor's workspace name is lossy (every run of non-alphanumerics becomes one dash; the drive letter's case varies), so the folder is RESOLVED rather than decoded: against known projects and their registered worktrees (read from `.git/worktrees`, no git process) it is `matched` when exactly one has that name, `ambiguous` when several do (none is picked), `project_only` for a `<drive>:\_scratch\<repo>-<suffix>` checkout of one known project (grouped under it, labelled "checkout not identified", no folder claimed), and `unmatched` otherwise; every state keeps the chat listed. On the measured machine: 75 rows (was 49), 42 matched, 4 project-only, 28 unmatched (deleted scratch test folders). The Cursor scan cap is now 200.
