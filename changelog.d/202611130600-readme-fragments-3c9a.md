### Added
- (docs) **README fragments: a PR adds a file under `readme.d/` instead of editing `README.md`.** Two PRs that documented the same README section conflicted on it (it happened while merging the Cursor handoff work), which is exactly what changelog fragments removed for `CHANGELOG.md`. New `helpers/readme_fragments.py` (stdlib only, launcher `scripts/readme_fragments.py`) with `targets`, `new <slug> <section>`, `check`, `preview` and `build`. A fragment's first line names a `<!-- help:KEY -->` section of the README and the rest is Markdown appended to the END of that section: before the first `---` rule that is followed by an anchor, a `#`/`##` heading or the end of the file, so a footer such as `## Credits` stays below it. `check` rejects an unedited template, an unknown section, a level-1/2 heading, an anchor comment, a conflict marker, an unclosed fence, an empty body, two fragments saying the same thing, and any `.md` in `readme.d` that is not named like a fragment (it would never be folded). `build` validates everything first, writes README.md before deleting anything, keeps its CRLF line endings, and recovers from a failed deletion without duplicating text. The suite validates the real fragments (`tests/test_readme_fragments.py`). Until `build` runs at release preparation, README.md and the in-app Help from a checkout do not show a pending fragment. Not done: the Release Wizard does not fold README fragments yet, so run `build` and commit it before the Wizard (its pre-flight refuses a dirty tree). (`src/helpers/readme_fragments.py`, `scripts/readme_fragments.py`, `readme.d/README.md`, `tests/test_readme_fragments.py`)
