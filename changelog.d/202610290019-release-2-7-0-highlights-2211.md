### Added
- (release) **A Windows installer beside the zip.** `Tokensave-Manager-v2.7.0-windows-setup.exe` installs all three executables per user (no administrator) or for all users, upgrades in place, and uninstalls with two unticked boxes for your settings and logs. It is built from the validated zip and proved by really installing, upgrading and uninstalling a test build of it. Unsigned, so SmartScreen will say "unknown publisher".
- (release) **Releases are built and drafted by a workflow from the tag.** A `v<version>` tag builds on a clean Windows runner, smoke-tests what was built, attests where the files came from and creates a DRAFT GitHub release; nothing publishes until you press Publish. The Release Wizard hands over to it instead of creating a second release.
- (release) **A versioned zip with checksums, a smoke test that runs what was built, and one version number.** The zip unpacks into its own versioned folder with `SHA256SUMS.txt`; the three executables are run layer by layer, first-run and configured, and the MCP wrapper is sent a real `initialize`. `constants.APP_VERSION` is the one number everything else is tested against.
- (config) **Settings live in `%LOCALAPPDATA%\TokenSaveManager\`, and the first run copies the old ones.** Replacing or moving the program folder no longer touches them. The copy is verified, never overwrites and never deletes the original.
- (help) **Help is the repository's own documentation: 59 topics instead of 25, read-only in a build.** The documents are compiled into the executable and also into one self-contained HTML page the Help tab opens in your browser at the topic you were reading. A link that points at nothing stops the build.
- (changelog) **Changelog fragments, so parallel pull requests stop conflicting.** Each PR adds a small file; the Release Wizard drafts the notes from them and consumes them in the release commit.
- (settings) **Settings is a tab, with a Save/Revert bar that appears only when something changed.** Save is one staged step, so a half-applied configuration can no longer happen.
- (instructions) **The shared rules now reach every project.** Each project commits a copy of the baseline, the Instructions panel shows which projects the chain actually resolves for, "Move into CLAUDE.md" retires the middle file, large instruction files can be split, and the shared gotchas are delivered into each project.
- (mcp) **An MCP Overview page, a Claude Desktop chat switch and per-project binding.** One answer replaces five panels, and a project's own tokensave entry can be bound or unbound with a toggle.
- (policy) **Agent Policy: commit and push are separate switches, both off by default.** A Stop hook can record what a session was for, and PR drafts can use it as a fourth grounding source. The shared baseline is the compiled output of those choices, never a second source of truth.
- (adherence) **A post-read nudge steers agents back to `tokensave_read`.** Measured against all wired projects, where the rule was current and produced no reads.
- (agents) **Cursor is a peer of Claude Code, PyScope an optional peer of tokensave, and there is a written contract for making a project callable by an agent.** Adding another agent is a table row.
- (tools) **ruff, pyright and markdownlint can be installed from the GUI, and their findings are kept apart from the editor's.** Two sources are shown as two, never summed into one number.
- (doctor) **New Doctor checks: extra checkouts nothing tracks, tracked `vendor/` code the index hides, which tokensave built each graph, and index freshness.**
- (tasks) **The Tasks tab has an Active sessions view and an MCP servers view, and Cursor chats appear in it.**
- (projects) **Force Sync All, Rename Project…, and one batch commit prompt for what a bulk action wrote.** Messages are built from rules and only files the Manager can prove are its own are staged.
- (ui) **The OUTPUT pane can be selected, copied, dragged taller and popped out into its own window.**
- (tokensave) **tokensave 7.12 to 7.15 are integrated, and the integration check says which version you came from and what changed.**
- (drive) **A driven run can start while the real Manager is open, leaves evidence, and its exit code means something.** There is also a driver that runs a real VS Code and looks at it.

### Changed
- (architecture) **The oversized modules and classes are split under their caps.** The file-length aspiration moved from 800 to 1,000 lines and the two caps that were walls became gates.
- (extension) **The extension activates once VS Code has finished starting.**

### Fixed
- (instructions) **The shared baseline had never loaded in any project, and 532 lines of load-bearing rules with it.** Claude Code does not follow an absolute include outside the project, so each project now carries a copy.
- (mcp) **Claude Desktop's app-level tokensave entry shadowed every project's own.** The trust flag has to be read off the forward-slash spelling, and the retirement guard counted an untrusted project as ready.
- (git) **Every PR draft ticked "Test suite passes locally" with a number no test run produced.**
- (startup) **Two startup dialogs had never opened, Quit ran on the tray's thread, and the update poller logged into a queue that did not exist yet.**
- (graph) **Every graph read answered about the default branch, whichever branch you were on.**
- (release) **Releasing no longer rewrites a CRLF `CHANGELOG.md` as LF, and the version resource is read from the right fields.**
- (tasks) **The Tasks tab no longer raises `TclError: Item ... already exists`.**
- (doctor) **One file in another encoding no longer ends the whole Doctor run.**
