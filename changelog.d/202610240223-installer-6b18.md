### Added
- (release) **A Windows installer (`Tokensave-Manager-v<version>-windows-setup.exe`) beside the zip.** `build.ps1 -Release -Installer` compiles `packaging/tokensave-manager.iss` with Inno Setup 6 from the **validated zip's own contents**, so the installer can never carry a file the zip's inventory check refused (a config, a log, a missing executable), and adds it to the same `SHA256SUMS.txt`. It installs all three executables, `templates/` and `docs/`; per-user by default (no administrator), all-users on request. An upgrade replaces the programs in place under one AppId and deletes `templates/` and `docs/` first so nothing stale lingers; settings and logs live in `%LOCALAPPDATA%\TokenSaveManager\` (the config move), not in the install folder, so an upgrade cannot reach them. Uninstall asks two questions, both unticked: remove the settings, remove the logs. A silent uninstall keeps everything unless `/REMOVESETTINGS=1` and/or `/REMOVEDATA=1` is given; removal is confined to a folder named for the application, deletes those files by name, and removes the folder only if it is then empty, so a file a person kept there survives. The shipped build waits for a running Manager (its single-instance mutex). **It is proved by installing it:** before the shipped installer is compiled, `helpers/installer_drive.py` builds a TEST variant of the same script (its own AppId, its own data folder) and really installs it into a folder with a space, smoke-tests the installed application with the same layers as the zip, upgrades over it (a planted stale file must go, settings and logs must stay), and runs every uninstall option, a file the person kept, and a data folder not named for the application; it refuses to run if the real AppId is registered, and removes only a leftover TEST registration. The uninstaller hands off to a temporary copy and returns at once, so the driver waits for Inno's closing log line rather than trusting an exit code (the first run raced and passed a log-removal check that had not happened yet). The release workflow installs Inno Setup 6.7.3 pinned by sha256 and attaches the setup file to the draft. Not covered: the all-users path (it needs a person to approve elevation) and the interactive uninstall form. **Unsigned**: SmartScreen will say "unknown publisher". `tests/test_installer.py` holds the structure, the build code and the real driven run (skipped without Windows and Inno Setup); six mutations of the script (upgrade no longer clearing, the folder-name guard dropped, logs removal deleting the whole folder, settings removed by default, settings removal also removing logs, the empty-folder cleanup removed) each fail it.
