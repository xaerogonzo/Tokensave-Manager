### Added
- (help) **The Help documents are compiled into one read-only HTML page, and the Help tab opens it.** The Tk pane shows the documents as styled text but has nowhere to send a reader: links lose their URL, tables stay monospace and nothing prints. `src/helpers/markdown_html.py` (standard library only) compiles the same markdown subset into ONE self-contained page: a contents list, every document, real tables, working links, light and dark, printable. It has no script, loads nothing (a Content-Security-Policy meta forbids everything but its own inline style), escapes every character of document text, and shows inline HTML as typed. Links: `#heading` and links between the help documents resolve to ids in the page; `http(s)` and `mailto:` become real links with `rel="noopener noreferrer"`; a source file, `javascript:`, `file:` or `data:` renders as its text; a link into the help that points at a heading or document that is not there stops the compile instead of quietly turning into text (the seven documents have none today). It is **compiled at build time** and rides in the executable's help bundle with its own digest (`PAGES_*` beside the markdown literals), so a build never compiles a page and never reads the loose copy; a checkout compiles the documents on disk, so an edit shows without a build. In a build the Help tab's button becomes **Open in browser (read-only)**: it writes a read-only temporary copy of the page with `{{placeholders}}` filled by HTML-escaped values for this machine (a path with `&` or `<` cannot become markup) and opens it at the topic you are reading, falling back to a read-only copy of the bundle's markdown if there is no page or no browser. The same page ships as `docs/help.html` (required by the zip inventory check), with the file-location placeholders described generally because it is compiled on the build machine and must not carry a developer's paths. The corpus verdict a build must pass now also requires the page and an anchor for every topic. **Measured: on all seven real documents the page and the Tk pane carry the same words in the same order** (13,351 in the README alone), and a test holds them to it, so the two presentations of one document cannot drift. `tests/test_markdown_html.py` (44 tests); eleven mutations (text left unescaped, `javascript:` allowed, `rel` dropped, the policy dropped, dead links not recorded, images kept, an unclosed bold left open, the table separator kept as data, placeholder values unescaped, dead links no longer stopping the compile, the page left writable) each fail it.
