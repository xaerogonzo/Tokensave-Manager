### Added
- (agent-cli) **Choose a different agent for one job.** Settings → AI → Agent per feature sets `agent_overrides` for commit messages, Draft PR, code review, test generation, the Ask tab, the refactor scout and the integration audit; every row defaults to "inherit", which is the existing `agent_cli`. The rules are the ones the default already had, extended rather than loosened: a named agent that is not installed is reported as unavailable and does **not** fall back to the default, an unrecognised id (or an `agent_overrides` that is not an object) is an error that names the feature, and the model and path follow the agent that was chosen. Settings writes the key only when something differs from the default, carries through overrides it does not list, and shows a stored value it does not recognise as itself rather than as "inherit", because showing it as the default would make the next Save erase it. `cfg.resolve_agent_cli(feature)` and `resolve_from(cfg, feature)` take the feature; the default call is unchanged. A guard test fails any new call site that omits one, and was checked by removing one. There is deliberately no fallback policy yet. (`src/helpers/agent_cli.py`, `src/state.py`, `src/dialogs/settings_ai.py`, `tests/test_agent_routing.py`, `tests/test_settings_tab.py`)
