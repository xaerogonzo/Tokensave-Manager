### Added
- (release-wizard) **The Release Wizard folds README fragments (`readme.d/`) in its release-prep commit.** Until now `python scripts/readme_fragments.py build` had to be run by hand and committed before the Wizard, because the pre-flight refuses a dirty tree. When `readme.d/` has fragments, Publish now validates them first (an invalid one blocks Publish with nothing changed, like `changelog.d`), folds them into `README.md` before the build (a built Manager compiles README.md into its Help), and commits `README.md` plus each `git rm`'d fragment in the SAME commit as the CHANGELOG. It does not depend on the CHANGELOG sync box. The confirmation counts the README fragments; a failure names `git restore --staged --worktree README.md readme.d`; a re-run after a later failure sees the fragments as already folded and does not fold twice. Pre-flight accepts a modified `README.md` only while fragments are pending. A project without `readme.d/` runs the exact pipeline it had. (`src/dialogs/release_wizard.py`, `src/controllers/git_tab.py`, `src/helpers/readme_fragments.py`, `tests/test_release_readme_fragments.py`)
