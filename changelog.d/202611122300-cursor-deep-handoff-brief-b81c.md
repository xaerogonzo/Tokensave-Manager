### Added
- (handoff) **A Cursor session now hands over its whole conversation, not its last ten prompts.** The brief carried the first prompt, ten one-lined prompts and ONE assistant message: on the measured 763 KB desktop chat, 34 prompts, a plan, a question, 64 edited paths across five checkouts and 171 shell commands were reduced to a sliver. New `helpers/handoff_digest.py` streams the transcript once (bounded; one bad or oversized record is skipped and counted) and writes a brief with: every prompt paired with how THAT turn ended (Cursor's own `turn_ended` status, so a last turn that stopped on "Weekly usage limit reached" says so), the plans, checkpoints and questions the agent recorded (an answer is only ever the person's next message, never inferred), the files it touched and its last shell commands, and the last prompt. Cursor transcripts record NO tool results (0 in 25), so files and commands are labelled attempted, and each file is cross-checked against `git status` now in the checkout it belongs to (a chat can edit several worktrees). Hard limit of 60 KiB UTF-8, enforced per section so the pointers and repository state can never be the part that is cut; every omission (turns in the middle, shortened prompts, paths, commands, sections cut) is counted in the brief. Everything is redacted before it is truncated, so a secret cut in half is still masked. The whole conversation (secrets masked, no tool payloads, capped at 1 MiB with the cut stated) is written beside the brief as `<id>.conversation.md` and the launch text points at both. Whether git ignores `.tokensave/handoffs` is asked of git, not assumed, and warned about in the brief. A transcript with no readable prompt falls back to the old short brief. The original transcript is only read. (`src/helpers/handoff_digest.py`, `src/helpers/agent_handoff.py`, `tests/test_handoff_digest.py`)
